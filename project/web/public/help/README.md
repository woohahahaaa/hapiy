# hapiy 帮助文档

## hapiy 是什么

hapiy 是一套**自托管的 LLM API 网关**。它对外提供与 OpenAI 兼容的 HTTP 接口（`/v1/chat/completions`、`/v1/completions`、`/v1/embeddings`、`/v1/images/generations`、`/v1/audio/speech`、`/v1/audio/transcriptions`），对内把请求按你在「转发拓扑」里画出的可视化流程，转发到你配置的上游供应商——OpenAI、Anthropic 兼容服务、自建或第三方中转都行。客户端只需要改一个 BaseURL 和一把令牌 Key，就能把各种应用接到统一的模型出口上。

围绕转发链路，hapiy 还提供：供应商与密钥池管理、令牌签发与额度、请求/响应改写、并发控制、故障转移与自动恢复、渠道亲和性、请求/响应日志抓取、用量与费用统计，以及把常见 AI Agent 软件（opencode、ChatGPT/Codex、openclaw 等）接入本系统的「接管Agent」。所有数据保存在本地 SQLite，单进程部署，适合在自己的服务器或局域网上运行。

一个请求的完整旅程：客户端带 `Authorization: Bearer hk-...` 调用 hapiy → 令牌鉴权 → 按转发拓扑（请求入口、条件开关、供应商插槽）选出一个可用的上游供应商与 Key → 执行请求改写 → 并发控制 → 调用上游 → 响应改写 → 写使用记录并累计用量。

## 快速开始

第一次使用，按下面四步就能搭好第一个 API 转发工作流。

### 第 1 步 添加供应商

进入「模型接入 → 供应商」，点「添加供应商」：

- **名称**：随便起，全局唯一。
- **Base URLs**：上游的接口地址，例如 `https://api.openai.com/v1`，每行一个。
- **API Keys**：上游密钥，每行一个，可加备注。
- **模型**：添加上游支持的模型名（区分大小写）；也可以点「从上游获取模型」自动拉取。
- **Endpoints**：不填表示不限制请求路径。

保存后确认这一行状态是「启用」。

### 第 2 步 创建令牌

进入「模型接入 → 令牌」，点「添加令牌」，填名称（额度可留空 = 不限制），保存。然后点列表里的复制图标，拿到 `hk-` 开头的完整 Key——客户端就用它来调用 hapiy。

### 第 3 步 搭建转发拓扑

进入「转发拓扑」：

1. 在画布空白处右键，选「添加完整工作流」，自动生成「请求入口 → 供应商 → 故障转移 → 请求改写 → 响应改写 → 并发控制 → 日志抓取」整条链。
2. 在「供应商」插槽里点添加，用「选择供应商」下拉绑定第 1 步建好的供应商。
3. 确认请求入口右上角的开关是打开状态（权重保持 1）。

拓扑改动会自动保存，不需要手动保存按钮。

### 第 4 步 调用验证

用刚才的令牌发起一次请求：

```bash
curl http://<hapiy 地址>/v1/chat/completions \
  -H "Authorization: Bearer hk-你的令牌" \
  -H "Content-Type: application/json" \
  -d '{"model":"你的模型名","messages":[{"role":"user","content":"你好"}]}'
```

`model` 必须在供应商的模型列表里（区分大小写；模型列表留空则表示接受任意模型名）。请求成功后，可以在「监控 → 活动监视」看到请求流过拓扑的动画，在「使用记录」里查到这次调用的耗时和 token 用量。

### 调用失败时

| 现象 | 原因 |
| --- | --- |
| 401 `invalid token` | 令牌错误、被禁用，或没带 `Authorization: Bearer` 头 |
| 403 `quota exceeded` | 令牌额度已用完 |
| 503 `无法为 xxx 找到可用供应商` | 拓扑里没有可用路由：检查模型名大小写、供应商是否启用、入口是否开启、拓扑是否接线 |
| 404 `路径不存在` | 调用了不支持的接口路径，或供应商 Endpoints 白名单不允许该路径 |

## 转发拓扑

「转发拓扑」是整个系统的核心页面：用可视化流程图描述「请求进来之后走哪条路」。页面标题下方的状态行会显示当前激活的请求入口数和节点数。

### 画布操作

- **右键空白处**或点右下角「添加节点」，弹出添加菜单：添加完整工作流、添加请求入口、添加供应商插槽、添加各类规则插槽（请求改写/响应改写/并发控制/故障转移/日志抓取）、添加条件开关、添加应急供应商。
- **连线**：从节点右侧圆点拖到下一个节点左侧圆点。不合法（成环、重复插槽、节点多条出边等）的连接会被拒绝并提示原因；把连线端点拖到空白处可以断开。
- **框选**：点右下角「框选模式」，拖拽画出选框，选中多个节点。
- **删除**：选中节点后按 Delete 或点左下角删除按钮，弹确认框；只选中连线则直接断开，不弹窗。
- **撤销 / 重做**：`Ctrl/Cmd+Z`、`Ctrl/Cmd+Shift+Z`；最多回退 100 步，刷新页面后清空。注意：撤销只影响拓扑数据，不影响节点摆放位置。
- **复制 / 粘贴**：`Ctrl/Cmd+C`、`Ctrl/Cmd+V`，复制选中的子图。
- 右下角还有「自动布局」「最大化显示全部节点」「模型节点色值」（配置模型节点流光颜色，HEX 色值、空格分隔）。

### 节点类型

| 节点 | 作用 |
| --- | --- |
| 模型中心 | 派生展示，列出所有可用模型；点击模型名可复制。不需要手动连到它 |
| 请求入口 | 工作流的起点，右上角开关 + 权重；权重 0 等于停用 |
| 供应商插槽 | 绑定一个或多个供应商；右上角按钮切换选择策略：按顺序 / 随机 / 轮询 |
| 请求改写插槽 | 绑定请求改写规则，可放多条、拖动排序 |
| 响应改写插槽 | 绑定响应改写规则 |
| 并发控制插槽 | 内联配置「每 X 分钟内最多 N 条」，每个插槽一条 |
| 故障转移插槽 | 绑定故障转移规则 |
| 日志抓取插槽 | 抓取请求/响应原文；创建时默认关闭，点右上角开关可设置开启时长 |
| 条件开关 | 按供应商/模型筛选或请求头、请求体条件决定走「是」还是「否」分支 |

### 请求怎么流动

- 一个请求从**启用的请求入口**出发，沿连线经过供应商插槽（内部选中某张供应商卡）再到后续插槽。每个节点最多一条出边，只有条件开关有「是/否」两条。
- 多个入口都有可用供应商时，按入口权重加权分流；权重 0 或开关关闭的入口不参与。
- 「应急请求入口」只在普通入口全部找不到可用供应商时兜底启用；普通链路恢复后自动切回。应急链路会用警示色标出。
- 某个插槽如果从任何启用的入口都走不到，会整体变灰、不可交互（「日志抓取」除外，它自带开关）。变灰不代表数据丢失。
- 条件开关按每个请求实时判断：供应商/模型筛选命中，或请求头/请求体条件命中，即从「是」输出；两个分支互斥。什么都不配置时默认走「是」。

### 保存与历史版本

- 任何修改都会在约 0.4 秒后自动保存；保存失败会提示并自动重试。
- 节点位置（布局）单独保存，与拓扑数据互不影响。
- 点右上角「历史版本」可以预览和恢复历史版本；恢复前会自动把当前版本存档，随时可以回退。系统每 5 分钟自动保留一个稳定版本，最多 20 个。
- 如果同一个拓扑在别的页面被改过，会提示刷新，不会自动合并。

## 模型接入

### 供应商

「供应商」页面维护上游 API 供应商，也就是请求最终要转发到的地方。

列表每行显示名称、Base URLs、Keys、Endpoints、模型、状态和故障转移情况，可以启用/禁用、编辑、删除。

新建/编辑表单的字段：

- **名称**：必填，全局唯一，重名会被拒绝。
- **Base URLs**：每行一个；保存时自动去掉结尾的 `/`。**第一个地址**用于「从上游获取模型」。
- **API Keys**：每行一个 Key，可加备注；**第一个 Key** 在拉取模型时可选是否携带。
- **Endpoints**：允许访问的路径白名单（如 `/chat/completions`），请求路径必须精确匹配其中之一；留空表示不限制。
- **模型**：每行一个模型名，可分别配置价格和 Endpoint；模型列表留空表示接受任意模型名。
- **模型价格**：三种模式——
  - 单独设置价格：输入/缓存写入/缓存读取/输出四项（每 1M token），必须以 `$` 或 `¥` 开头，符号决定该模型的计费币种；
  - 从 models.dev 同步：选一个参考厂商，自动同步参考价格，可再填倍率（支持 `1/2` 这样的分数）；
  - 不设置：按 0 计费。
- **从上游获取模型**：按「模型列表接口」拉取上游模型；弹窗里可以「全选/全不选」，选择「添加」（合并去重）或「清空已有并添加」（整体替换）。
- **模型列表接口设置**（齿轮按钮）：拼在第一个 Base URL 后面的路径，可勾选是否传入第一个 Key；该设置在弹窗内即时生效。

页面上没有独立的「测试连接」按钮，要验证连通性可以直接用「从上游获取模型」。删除供应商不会自动删除拓扑里的绑定，记得去拓扑里清理。

### 令牌

「令牌」页面签发客户端访问 hapiy 用的 Key。

- **名称**：必填，全局唯一。
- **额度**：留空 = 不限制。每次请求成功后按 token 用量累计扣减；额度用完后该令牌的请求会被拒绝（`quota exceeded`）。
- **Key**：保存后由服务端生成，`hk-` 开头。列表里只显示前几位，点复制按钮复制的是完整 Key。
- 支持启用/禁用和删除。删除后使用该令牌的请求立即失效，不可恢复。

客户端调用方式：

```text
Authorization: Bearer hk-xxxxxxxx
```

注意：令牌没有过期时间、分组、模型白名单配置；页面上也没有轮换 Key 的按钮（直接新建一个即可）。

## 请求处理

### 请求改写

「请求改写」规则用来在上游调用之前修改请求。规则由若干**规则块**组成，每个块 = 一组条件 + 一组执行动作：条件满足才执行动作，条件留空表示无条件执行。

**条件**：

- 作用域选 `header` 或 `body`，路径填 header 名或 gjson 路径（如 `model`、`messages.0.content`、`messages.-1.content`）；
- 操作符：包含、以前缀开头、以后缀结尾、等于、不等于、大于、大于等于、小于、小于等于、正则匹配；
- 值需要按 JSON 写法：固定字符串要带引号（`"hello"`），`true/false/null/数字` 是字面量；不带引号的裸文本不合法，保存时会被丢弃；
- 可以勾选「反向匹配」，或用 `AND（都满足）/ OR（任一满足）` 组织多个条件。

**执行动作**（按顺序串行）：设置值、删除字段、追加字符串、前置字符串、流式首段前置、流式末段追加、去除前缀、去除后缀、确保前缀、确保后缀、去首尾空白、转小写、转大写、字符串替换、正则替换、重命名/移动、复制。其中 `move`/`copy` 在 header 作用域下不可用。

「设置值」的写法：不加引号 = 变量引用（取原始请求里的同名 header 或同路径 body 值）；`true/false/null/数字` = JSON 字面量；加引号 = 固定字符串。

**测试**：页面右上角「测试」按钮可以选规则、输入 JSON 请求体，立即看改写结果。测试只覆盖请求体，header 类动作的结果不会体现在输出里。

**绑定**：规则建好后必须到「转发拓扑」的「请求改写」插槽里选中它才生效；一个插槽可以放多条，按顺序依次执行。

### 响应改写

和请求改写用法相同，但作用对象是上游返回的响应。可用动作有四种：重命名字段、加前缀、加后缀、删除字段。非流式响应整体改写（会同步修正 `Content-Length`）；流式响应逐个 SSE 事件改写，「加前缀」只发生在第一个匹配事件上，「加后缀」会等到流结束后补上。

注意：响应改写在流式场景下不执行条件判断，条件只在非流式响应里生效。

### 故障转移与自动恢复

「故障转移」页面配置：主通道失败时怎么换通道、什么时候把坏通道标记为禁用。

规则字段：

- **转移维度**：Base URL / Key / 供应商；
- **自动禁用**：命中后是否累计次数并禁用出问题的通道；
- **触发条件**：首字超时（秒）、速度限制（token/s）、上游报错内容包含关键词；
- 新建规则默认在**任何非 2xx 响应**时触发。

达到「禁用阈值」（每 X 分钟命中 N 次）后，系统会把对应通道标记禁用并记一条「故障转移」事件。规则同样需要到「转发拓扑」的「故障转移」插槽里绑定才生效。

「自动恢复」Tab 负责把被禁用的通道恢复回来，两种模式：

- **测试上游恢复**（推荐）：按间隔（分钟）轮询，用被禁用时保存的请求复测，通过且满足原规则条件才恢复；0 = 关闭；
- **定时恢复**：禁用后倒计时归零直接恢复，不做探测。

「待恢复记录」列表里可以查看被禁用的对象：点「测试上游」会打开预览并试着复测，点「直接恢复」立即解除禁用。「测试方法」用来配置复测时如何简化保存的请求体（比如把消息内容替换成「你好」、去掉大字段），以及没有请求体的记录冷却多久后尝试恢复。

### 渠道亲和性

「渠道亲和性」让同一个会话在多次请求间**优先复用上一次用过的供应商 + Base URL + Key**，避免多渠道轮换把上下文拆散（对依赖上游缓存、会话状态的服务很重要）。

有两种模式：

- **规则亲和**：一条条规则，配置 Session ID 请求头（每行一个，大小写不敏感）、Model gjson 路径（留空则用请求体里的 `model` 字段）、缓存有效期（秒）。按规则顺序取第一条能取到 Session 的规则生效。缓存是内存态，重启后丢失。
- **兜底亲和**：全局开关，同样配置 Session/Model 字段，把上次成功的渠道记到数据库，无过期时间。

生效顺序是：兜底亲和 → 规则亲和 → 正常拓扑选择；命中还要求渠道仍在当前可用集合内。触发故障转移时，会同时清掉亲和记录，避免继续粘在失败通道上。

### 并发控制

并发控制不在「请求处理」页配置，而是加在「转发拓扑」的「并发控制」插槽里，内联填写「每 X 分钟内最多 N 条」。

运行语义：请求进入即占用一个名额，请求完成后从完成时刻起倒计时，到期释放；达到上限的请求会**排队等待**（不会立即报错）。同一个插槽节点被多条链路共用时，共享同一个窗口。多个并发插槽同时存在时，必须全部通过才算通过。

## 监控

### 活动监视

实时查看正在进行的请求和运行统计。

- 顶部是统计卡片：总请求、成功、失败、总 Token、平均延迟、成功率、花费、吞吐量、缓存命中率，可用日期筛选切换范围；「清空用量」只清统计，不动请求记录。
- 下方「活跃请求」表每 2 秒刷新，显示每个请求当前所处阶段（排队中、连接上游、等待响应、接收中等）、首字耗时、渠道亲和性等；未结束的请求可以「掐断」。
- 点击已结束的行可以打开该请求的详情；「显示 N 内的活跃请求」可以调整已结束请求在列表里的保留时长。

### 使用记录

按请求记录每次调用的详情，是排查问题和看用量的主要入口。

- 列表字段：时间、来源、令牌、供应商、模型、渠道亲和性、Tokens（输入/缓存写入/缓存读取/输出及命中率）、流式、消耗、耗时（总耗时和首字）、速度、状态。
- 支持按日期、类型（请求/故障转移/自动恢复/手动恢复/系统管理）、来源、令牌、供应商、模型、状态筛选。
- 点任意一行打开详情：上游 URL、上游 Key（默认模糊，悬停可见）、分阶段耗时（排队/请求改写/连接/首字/响应改写/流式改写）、失败原因等。
- 日志是批量写入的，新请求可能延迟几秒才出现；页面不自动刷新。
- 「清空」会按当前筛选条件删除记录且不可恢复——注意当前版本「类型」筛选不会参与清空条件，「清空当前页面的」实际删除的是所有匹配记录。

### 日志抓取

查看抓取到的请求/响应**原文**，包括改写前后的差异。

- 抓取开关不在这里：要到「转发拓扑」的「日志抓取」插槽打开开关并设置开启时长（到点自动关闭），插槽里还可以勾选记录请求、记录响应，并设置日志前缀（作为筛选用的文件夹）。
- 列表按请求成对展示，显示时间、文件夹、令牌、供应商、模型、来源、类型（请求/响应/请求+响应，可带「修改过」「报错」标记）、文件名/请求 ID、大小。
- 点行打开预览：可分别查看请求头/体、响应头/体；被规则改写过的内容会用对比视图展示；流式响应支持「整合 JSON」或按事件查看原始内容，每个节点都可以复制。
- 清空操作同样不可恢复；注意当前版本按筛选清空时只会带上文件夹、来源、日期条件。

## 接管Agent

「接管Agent」用于把外部 AI 软件（内置支持 opencode-v1/v2、WorkBuddy、ChatGPT(Codex)、openclaw）的配置文件纳入 hapiy 管理：检测路径、修改内容、把模型接入信息写进去，让这些软件直接走 hapiy 网关。

### 管理规则

每种软件类型对应一条「接管规则」，描述它的默认配置文件路径（Windows/Mac）、provider/model 在配置里的字段路径、模型信息字段的写法、公共配置推荐值等。系统已内置常见软件的规则，通常不用手动加；也可以「添加接管规则」自定义。

规则编辑支持表格和 JSON 两种模式：JSON 模式里可以携带注释，适合把整份规则复制给其他 Agent 参考。编辑内置规则后可以「使用默认推荐模版」恢复默认。

### 配置文件

「配置文件」页面管理被接管的配置文件记录：

1. 点「接管新的配置文件」，填记录名称、选择软件类型、选择连接方式：
   - **本机**：选系统（Windows/Mac/其他），填路径，可「同步预设Agent信息」自动填入默认路径，输入后会自动检测文件是否存在；
   - **SSH**：填主机、账号、密码或私钥（支持跳板机），填远程路径，点「测试 SSH 读写能力」验证连接、读取、写入三项都通过。
2. 保存后，点「编辑配置文件」可以直接在网页里查看和修改该文件的 JSON（保存前会校验格式，也提供历史版本）；点「管理模型」可以套用推荐配置或推荐模板、对比差异并应用。
3. 想让该 Agent 走 hapiy，就在「管理模型」里「添加托管供应商」：选择规则、填入在「令牌」页创建的 Key，系统会生成包含 hapiy 地址和 Key 的接入配置，点「同步到配置文件」写回文件。

### 启用开关

「接管Agent」入口默认隐藏在侧边栏之外，需要在「系统设置 → 开启接管Agent」（地址 `/settings/other`）里打开开关。打开后**刷新页面**，侧边栏才会出现入口。开关只控制菜单显示，不影响功能本身。

## 系统设置

### BaseURL

配置系统的对外地址，主要给「接管Agent」的托管配置使用：

- **域名**：默认取当前网页域名，包含端口；
- **后缀**：默认 `proxy`；
- 最终 BaseURL = 域名 + 后缀，可一键复制；
- **标记来源**：每个来源名会生成一个 `.../__来源名` 形式的地址，用于区分不同客户端来源，可在标记里查看调用来源。

### 获取模型列表

- **默认模型列表接口路径**：供应商「从上游获取模型」时的默认接口，默认 `/v1/models`；
- **hapiy 模型列表接口路径**：对外暴露的模型列表路径，客户端可以用令牌带 `Authorization: Bearer hk-...` 请求它，返回已启用的模型名。

两个路径都必须以 `/` 开头。

### 币种汇率

- **全局消耗统计币种**：人民币 / 美元；
- **汇率**：1 美元等于多少人民币；
- 齿轮按钮里配置在线汇率接口（地址、字段路径、每天自动刷新），支持「测试接口」和「保存并刷新」。

币种和汇率只影响之后新产生的记录，历史记录保持当时的币种和金额。

### 查询Token用量

配置从上游响应里读取 token 用量的 gjson 字段路径。四类计数——输入、缓存写入、缓存读取、输出——各自可以配置多条路径，按顺序尝试，命中即停：

- 输入：`usage.prompt_tokens`、`usage.input_tokens` 等；
- 缓存写入：`usage.prompt_cache_miss_tokens` 等；
- 缓存读取：`usage.prompt_cache_hit_tokens`、`usage.prompt_tokens_details.cached_tokens` 等；
- 输出：`usage.completion_tokens`、`usage.output_tokens` 等。

保存后即时生效；「恢复默认」只是重置表单，还要点「保存」才写入。

### 数据备份

- **备份内容**：勾选要备份的模块，默认包含拓扑、供应商、令牌、请求处理规则、接管 Agent、系统设置；使用记录和日志默认不勾选；
- **自动备份频率**：从不 / 每天 / 每周；
- **相对路径**：备份文件存放位置，相对于后台服务所在机器，页面会实时显示解析后的绝对地址；
- 「立即手动备份」按当前界面勾选立即执行（不写回设置）；
- 下方历史列表可以按备份恢复，「恢复」会用备份覆盖对应模块的当前数据，覆盖前会自动生成一份安全备份。

### 其他

- 「Debug」菜单只在开发模式下显示，生产构建不可见。
- 「开启接管Agent」页面见上文章节。

## 用户资料

管理登录账号：

- **用户名**：修改后立即生效，用户名不能为空、不能与原来相同、不能与已有用户重名；
- **密码**：需要输入当前密码；新密码至少 8 位，两次输入需一致；
- **退出登录**：退出当前会话，返回登录页。

## 常见问题

**改完拓扑不生效？** 按顺序检查：供应商是否启用、拓扑里入口开关是否打开且权重不为 0、供应商插槽里卡片是否启用、模型名大小写是否匹配、插槽是否变灰（从任何入口都不可达）。规则类插槽还要确认绑定的规则没有被删除或停用。

**已经禁用的通道怎么恢复？** 「请求处理 → 故障转移 → 自动恢复」里看「待恢复记录」，可以「测试上游」或「直接恢复」；也可以在供应商编辑页里按 Provider / Base URL / Key 点「恢复」。

**使用记录有没有延迟？** 有，日志是内存批量写入，最多延迟几秒；「活动监视」里的活跃请求是实时的。

**费用和额度是一回事吗？** 不是。令牌额度按 token 用量累计扣减；「消耗」是按模型价格计算出来的金额，两者口径不同。

**帮助文档打不开或样式不对？** 帮助是独立的静态页面（`/help/`），由主程序直接托管，不依赖外网；如果通过自定义反代访问，确认 `/help/` 路径没有被改写或拦截。

**日志抓取为什么没有数据？** 抓取默认关闭：先到「转发拓扑 → 日志抓取」插槽打开开关并设置开启时长，并确认条目勾选了记录请求/响应、插槽接在正确的供应商链路下游。
