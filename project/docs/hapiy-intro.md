# hapiy 说明

## 一、hapiy 是什么，和 NewAPI、cc-switch 的区别

hapiy 跑在你自己的电脑或服务器上。你把各家模型服务——官方 API、中转站、自己搭的——都填进 hapiy，它对外就是一个统一的模型接口；你的 AI 工具（Claude Code、opencode、Codex 这些）只连这一个地址，配置一次以后就不用再动。换渠道、改请求、查问题、算花费，都在 hapiy 的面板里做，密钥和记录全留在本机，不需要注册任何账号。

和 NewAPI 比：NewAPI 是开中转站用的系统，强在渠道聚合、接口格式转换，把额度分发给一群用户。hapiy 用同样的聚合思路，但只伺候你一个人，方式也不同：每个功能都是一个节点，你把节点连成工作流，请求从入口进来，沿这条链路走到上游。常用的节点：

- **供应商**：一家模型服务（官方 API、中转站都行），可以带多个地址、多把 Key
- **请求改写**：请求发出去之前改它——补个请求头、改个参数、修掉客户端传错的值
- **响应改写**：上游返回的内容也能改——改字段名、加前后缀、删字段
- **故障转移**：哪家慢了、报错了自动换下一家；坏掉的先停用，探测恢复后再放回来
- **请求抓取**：把请求和返回的原文存下来，改写前后的对比也在，查「AI 工具发出去了什么、上游返回了什么」
- **并发控制**：给链路限速——每几分钟最多过几条，超出的排队
- **条件开关**：按模型或请求内容分流，让不同请求走不同的路

连好之后，一条请求走到哪、改了什么、花了多少钱，全程看得见。

最常见的组合长这样：**请求入口 → 供应商 → 故障转移 → 请求改写 → 响应改写 → 并发控制 → 请求抓取**。意思是：请求先选一家供应商，不行就按故障转移规则换下一家；发出之前改一遍请求，回来后改一遍返回内容；限速和原文存查挂在两侧。打开 hapiy 首页的「转发规则」，在画布空白处右键选「添加完整工作流」，这一整条链会自动生成，把供应商节点绑上你填好的那家，就能用了。

和 cc-switch 比：cc-switch 的本职是改 Claude Code、Codex 的配置文件来切换供应商，请求本身不经过它，哪家慢、哪次报错、花了多少钱它不知道。hapiy 的「接管 Agent」能做同样的事，还多出远程电脑和版本回滚；而且请求真的从 hapiy 走，切换才能自动，账才算得清。

一句话：NewAPI 管分发，cc-switch 管切换，hapiy 管你每一条请求的全程。

> 对比只讲思路差异，具体功能以各家当前版本为准。
