# hapiy 需求文档

## 项目定位

个人用的大模型 API 中转平台。买多家 Provider、多个 Key，通过本平台统一管理和中转。

**后端**：自研。Relay 层（HTTP 请求 → 透传上游 → 返回下游）参考 New API 的实现，但作为独立代码重写，不 fork 不 import 其包，以便在转发管道中插入以下自有扩展点：

- 请求改写 hook
- 响应注入 hook
- 实时事件推送（活动监视）
- 并发队列引擎
- 节点配置的序列化/持久化

**前端**：完全独立设计，不用 New API 的任何前端代码。

## 模块说明

### 转发拓扑（首页）

全屏节点视图，可视化编排路由拓扑。节点类型：

- **Endpoint** — 请求入口，绑定令牌和可用模型
- **Route** — 路由规则，匹配条件后分发到下游 Channel
- **Channel** — 绑定某个供应商的特定 Key + Base URL
- **自动切换节点** — 挂载到 Route 上，拖拽 Key / BaseURL / Provider 三个槽位决定故障切换优先级
- **自动回复节点** — 挂载到 Route 上，上游无输出超时后自动插入心跳消息

### 供应商

| 模块 | 说明 |
|------|------|
| 供应商 | 上游厂商配置：名称、Base URL、Key（可多个）、支持模型、协议模式（名称 + 路径后缀） |
| 通道 | 实际转发单元：绑定一个供应商的某个 Key + 某个 Base URL，可配权重 |
| 自动切换规则 | 全局健康检查：429 → 跳过/调货，500 → 自动封禁；定时恢复或自检后恢复 |

### 令牌管理

下游 API Token：名称、额度限制。

### 策略配置

可挂载到节点图中的可复用规则：

| 模块 | 说明 |
|------|------|
| 请求改写 | 改写请求头或请求体（JSON 操作），每条规则 = 操作 + 目标字段 + 值 |
| 心跳回复 | 上游持续 ? 分钟无输出时，自动插入自定义消息（如 "连接正常，上游正在吐字但太慢"） |
| 并发控制 | 并发频率（每 N 分钟 M 次）、超时处理（掐断或排队） |
| 故障转移 | 全局健康检查：429 → 跳过/调货，500 → 自动封禁；定时恢复或自检后恢复 |

### 监控

| 模块 | 说明 |
|------|------|
| 活动监视 | 实时显示当前请求：连通中 / 发数据中 / 收数据中 / 排队中（含排队时间）/ 已断开。异常记录保留。已完成/失败的请求保留 1 分钟后移入使用日志。活动中的请求不进入使用日志 |
| 使用日志 | 已完成的请求历史记录。日志轮转：每 100 万行切新文件，异步写盘不阻塞。批量更新：配额/计数累积到内存，每 5 秒合并写 DB |

### 系统设置

| 模块 | 说明 |
|------|------|
| 安全 | 用户名+密码登录、防暴力破解、微软验证器二次验证 |
| 性能 | 磁盘缓存（大请求体自动写临时文件）、过载保护（CPU/内存/磁盘+队列深度超阈值→503）、性能指标采集（无锁热路径+双写内存+Redis）、连接池复用（MaxIdle=500）、混合缓存（Redis优先+内存LRU降级） |

## 关键设计原则

1. **节点即配置**：路由、自动切换、并发、改写、自动回复等规则，最终都在「节点图」中以节点形式被调用和编排
2. **规则可组合**：切换规则、禁用规则、改写规则、并发规则——全部可挂载到节点图中的 Route / Channel 节点上
3. **例外**：「使用日志」和「活动监视」不进入节点图，它们是纯查看页面，没有可调用的节点
4. **Model → Provider → (Key, BaseURL) 三层模型**：
   - 一个 Model 可以有多个 Provider
   - 一个 Provider 可以有多个 Key（解决额度）和多个 Base URL（解决卡死）
   - 自动切换节点拖拽 Key / BaseURL / Provider 三个槽位决定故障时的切换优先级

## 后端实现参考（New API 值得借鉴的模块）

以下模块的代码模式值得阅读学习，但作为独立实现重写，不直接引用：

| 模块 | New API 代码位置 | 实现要点 |
|------|-----------------|---------|
| 日志轮转 | `logger/logger.go` | `io.MultiWriter` 同时写 stdout + 文件；每 100 万行切新文件；异步 goroutine 切文件不阻塞请求 |
| 磁盘缓存 | `setting/performance_setting/config.go` | 请求体 > 阈值 → 写临时文件；转发完清理；有上限防磁盘满 |
| 过载保护 | `middleware/performance.go` | 每个请求前检查 CPU/内存/磁盘使用率 → 超阈值返回 503 |
| 混合缓存 | `pkg/cachex/hybrid_cache.go` | Redis 优先 + 内存降级；命名空间隔离；Pipeline 批量操作；2s 超时上下文 |
| 无锁指标采集 | `pkg/perf_metrics/` | `sync.Map` + `atomic.Int64` 热路径零锁；双写（内存+Redis）；后台 goroutine 定期刷库 |
| 批量更新 | `model/utils.go` | 配额/请求计数累积到内存 map，每 5 秒合并写 DB，减少写压力 |
| HTTP 连接池 | `service/http_client.go` | `Transport.Clone()` 自定义池参数；`MaxIdleConns=500`；代理客户端独立缓存 |
| 三层限流 | `middleware/rate-limit.go`<br>`middleware/model-rate-limit.go` | 全局 IP 固定窗口 → 模型级用户令牌桶 → 端点级用户限流；Redis Lua 脚本预加载 |
