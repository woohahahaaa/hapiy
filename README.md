## 📝 项目说明

hapiy 跑在你自己的电脑或服务器上。把你用的各家模型服务（官方 API、中转站、自己搭的）都填进去，它对外就是一个统一的模型接口；你的 AI 工具（Claude Code、opencode、Codex、openclaw 这些）连上它就行，配置只改这一次。以后换渠道、改请求、限速、故障转移、抓请求原文、看用量、算花费、改客户端配置，都在 hapiy 的面板里做。

密钥、日志、花费记录全部留在本机，数据是一个本地 SQLite 文件，单进程运行，不需要注册任何账号。

它主要帮你处理 Agent 调用模型时的麻烦：上游变慢、限流报错、客户端 bug、花费算不清。功能比较多，hapiy 不是装上就会用的软件，建议先照着下面的「典型场景」跑一遍，上手会快很多。不想先研究也没关系：内置助手可以直接替你做配置。

> 和目前市面上最火的两个同类工具对比一下。**NewAPI** 面向搭中转站的人，管渠道聚合和接口格式转换，把额度分发给一群用户。**cc-switch** 只管客户端切换：改 Claude Code、Codex 的配置文件来换供应商，请求本身不经过它。**hapiy** 用同样的聚合思路，但只伺候你一个人，还多管了全过程（请求改写、并发控制、故障转移、请求抓取、花费统计、Agent 配置文件接管）。请求真的从 hapiy 走，所以每家的快慢、报错和花销都有记录。

> [!TIP]
> 控制台默认监听 `0.0.0.0`，同一局域网就能打开。要通过公网或隧道访问，请自行加上 HTTPS 与访问控制，并在「系统设置 → Base URL」里把对外地址改对。

## 💡 典型场景

下面这些场景都来自真实使用。

| 场景 | 遇到的问题 | 怎么解决 | 效果 |
| --- | --- | --- | --- |
| 中转站波动 | 多家中转站忽快忽慢、突然限流，手动切配置很麻烦 | 全部加进「供应商」；在「故障转移」里设置触发条件（等太久没返回、速度太慢、上游报错）和自动禁用阈值，再挂到「转发规则」的链路上 | 哪家卡自动换下一家；平时仍优先走指定渠道，坏渠道恢复后自动放回 |
| 中转站全挂 | 集体瘫痪，或临时有急活需要更快的线路 | 在「转发规则」加「应急请求入口」并绑定官方供应商；普通入口照常优先第三方 | 普通渠道都不可用时才切官方兜底；任何一家恢复就自动切回 |
| 上游报错 | WorkBuddy 调 opencode go 的 GLM-5.3-flash，`max_token` 已按要求设置，上游仍报「太大」 | 在转发规则把「请求抓取」插槽打开、只抓这次请求，到「日志中心 → 请求抓取」导出请求和响应原文对比 | 确认是客户端把值传错了，几分钟定位 |
| 客户端 bug | 确认是客户端 bug，等它发版遥遥无期 | 在「请求改写」新建规则，把 `max_token` 改成上游接受的范围，挂到链路 | 请求发出前就被修正，任务马上能跑 |
| Agent 卡住 | 一直显示「工作中」，分不清上游慢还是客户端卡 | 看「转发规则」页面底部的活跃请求面板：连接状态、已收到第几段数据（chunk）、总耗时与首字耗时 | 定位卡在连接、首字还是流式接收，必要时直接掐断 |
| 算不清花费 | 各家中转站计价方式不同，缓存命中还有差价 | 在「供应商」里给模型单独配价；有公开价的从 models.dev 同步并设倍率，没有的逐个手填；在「系统设置 → 币种汇率」统一换算 | 所有渠道按同一口径统计，钱花在哪一目了然 |
| 多 Agent、多电脑 | 每换一家中转站、每上一个模型都要挨个改 JSON，容易漏参数 | 用「接管 Agent → 托管模型」一键同步已启用的供应商和模型；推荐配置排错；公司电脑开 SSH 远程编辑 | 改一处多处生效，有语法检查，改坏可回滚 |
| 模型报 502 | DeepSeek harness 用 opencode go 的 dsv4.1flash，上游说缺少 `x-opencode-session` | 在「请求改写」新增规则，把 `header.x-opencode-session` 设为已有会话头的值或固定标识，挂到链路 | 请求头补齐，502 消失，模型正常返回 |

## 🧩 功能一览

按控制台左侧菜单从上往下过一遍。

### 模型接入

「供应商」就是请求最终转发到的地方：一家可以带多个 Base URL、多把 Key，各自可选「按顺序」或「均衡」轮换；模型列表可以直接从上游拉取，每个模型可以配价格、可以限制哪些路径（Endpoints）能走。「令牌」签发客户端用的 `hk-` Key：只改客户端的 Base URL 和这把 Key，其余什么都不用动；额度想设就设，按 Token 用量累计扣减。

### 转发规则

「转发规则」是整个系统的核心页面：用节点把「请求进来之后走哪条路」画成一张流程图：请求入口（开关 + 权重）、供应商插槽、请求/响应改写、并发控制、故障转移、请求抓取、条件开关，按需拼接；右键「添加完整工作流」会自动生成一条推荐链。支持应急请求入口（普通线路全挂时兜底）、自动保存、撤销重做、历史版本（每 5 分钟自动存档，随时回滚）。

### 请求改写与响应改写

**请求改写**在上游调用之前动手：按请求头或请求体条件匹配，串行执行二十来种动作，比如设置值、删除字段、加前后缀、正则替换、复制/移动。客户端传错的值、缺的请求头，都在这里修掉，不用等客户端发版；规则改完先在页面里「测试」看结果，再挂到链路上。**响应改写**作用于上游返回：重命名字段、加前后缀、删字段；非流式响应整体改写，流式响应按 SSE 事件逐个改。

### 故障转移与自动恢复

「故障转移」配置主通道失败时换谁：按 Base URL / Key / 供应商三个维度转移，触发条件支持首字超时、速度太慢、错误信息包含关键词；可以只在本次跳过，也可以命中多次后直接把出问题的对象禁用。被禁用的通道由「自动恢复」负责捞回来：用当时保存的请求复测上游，通过才恢复；也可以不探测，倒计时到了直接恢复。

### 渠道亲和性与并发控制

**渠道亲和性**让同一会话优先复用上次用过的供应商 + Base URL + Key，避免多渠道轮换拆散上下文（对依赖上游缓存的服务很重要）；命中时会话头、模型字段、缓存时长都可配。**并发控制**挂在链路上：每 X 分钟最多过 N 条，超出的排队等待，不会直接报错。

### 活动监视

在「转发规则」页面底部，有一块可拖动高度的面板：实时列出每个进行中的请求，标明它走到哪一步（排队中、连接上游、等待响应、接收中，以及第几个 chunk、已收多少字节），附来源、令牌、供应商、模型、渠道亲和、是否流式、总耗时与首字耗时。跑飞了点「掐断」直接断掉；也能设置已结束的请求在列表里保留多久。

### 日志中心

**使用记录**页面顶部先是一排运行统计（总请求、成功 / 报错、成功率、总 Token（缓存命中去重）、缓存命中率、吞吐量、平均延迟、花费，可一键清空统计），下面按请求保存明细：耗时、Token（含缓存命中与写入）、消耗、状态，点进去能看上游 URL 和分阶段耗时。**请求抓取**把请求和响应的原文成对存下来，被规则改写过的内容用对比视图展示；AI 工具发出去的是什么、上游返回的是什么，这里看得最清楚。默认关闭，需要时抓一段时间。

### 用量与花费

每个模型可以单独定价（输入 / 缓存写入 / 缓存读取 / 输出），也可以从 models.dev 同步参考价再乘倍率；消耗按全局币种和汇率统一换算，汇率可以配置在线接口每天自动刷新。令牌额度按 Token 用量扣减，和「消耗」是两套口径，页面上分开看。

### 接管 Agent

「接管 Agent」把外部 AI 软件的配置文件收进来自己管：内置 opencode-v1/v2、WorkBuddy、ChatGPT(Codex)、openclaw、DeepSeek Harness（桌面版/Web 版）等规则；配置文件可以在本机，也可以在另一台电脑上（SSH，支持跳板机）。网页上直接查看和修改文件内容，JSON 保存时校验格式，YAML/TOML 按原文保存，都有历史版本；「管理模型」可以按推荐配置批量调整模型字段、对比差异再应用；「托管供应商」会生成带 hapiy 地址和令牌的接入配置，一键写回文件，以后换渠道只改 hapiy 一处。

### 内置助手

控制台右下角随时可以叫出内置助手：聊天模式只查询和回答，执行模式可以代为新建、修改、启停配置；写操作走的是真实界面，和你自己点一样有确认弹窗。模型不可用时还可以「直连」某个渠道调试单次请求，这组配置不会写回供应商。

### 系统设置

「Base URL」配对外地址和来源标记（不同客户端用不同来源名，使用记录里能分清是谁发的）；「高级查询」集中配置模型列表接口路径、Token 用量字段路径和币种汇率；「数据备份」支持按模块定时备份、手动备份和一键恢复（恢复前自动生成安全备份）；还有主题配置等。界面和站内帮助都是中英双语。

## 📦 安装

### macOS / Linux

先打开「终端」（Terminal）：按 `Command + 空格` 打开聚焦搜索（Spotlight），输入「终端」或「Terminal」，回车即可。

然后把下面这行复制进终端窗口，回车：

```sh
curl -fsSL https://raw.githubusercontent.com/woohahahaaa/hapiy/main/install.sh | sh
```

### Windows

先打开 PowerShell：点「开始」按钮（或按键盘上的 Win 键），输入 `PowerShell`，在结果里点「Windows PowerShell」；Windows 11 也可以搜「终端」（Terminal）。不需要管理员身份。

然后把下面这行复制进窗口，回车：

```powershell
irm https://raw.githubusercontent.com/woohahahaaa/hapiy/main/install.ps1 | iex
```

安装脚本做四件事：下载最新发行版、校验 SHA256、装到固定目录并加入 PATH、注册登录自启（macOS/Linux 用 launchd / systemd --user，Windows 用任务计划程序）。**重复执行即为升级**。想手动安装，可从 [Releases](https://github.com/woohahahaaa/hapiy/releases) 下载对应平台压缩包，解压后保持 `hapiy`（Windows 为 `hapiy.exe`）与 `webdist/` 同目录即可。设 `HAPIY_NO_SERVICE=1`（Windows 为 `$env:HAPIY_NO_SERVICE=1`）可跳过自启注册。

装好后浏览器打开 <http://127.0.0.1:18009>。默认端口 18009，实际端口写在 `~/.hapiy/port`（Windows 在 `%LOCALAPPDATA%\hapiy\port`）。首次启动会自动创建管理员：用户名 `admin`，密码随机生成、只在 `~/.hapiy/log/hapiy.log` 里打印一次（`Default admin created: username="admin" password="..."`），登录后到「个人资料」改密码。

## 🚀 快速上手

第一次打开会先走一个两步向导（可跳过）：连一个供应商、选要用的模型，做完就能转发请求。之后按下面四步把链路搭完整：

1. **添加供应商**：「模型接入 → 供应商」，填名称、Base URLs（如 `https://api.openai.com/v1`）、API Keys、模型列表；保存时选「添加到转发规则」自动接线。
2. **创建令牌**：「模型接入 → 令牌」，新建后复制 `hk-` 开头的 Key，客户端就用它调用 hapiy。
3. **搭转发规则**：「转发规则」右键空白处 →「添加完整工作流」，在供应商插槽里绑定第 1 步的供应商。
4. **调用验证**：

```bash
curl http://<hapiy 地址>/v1/chat/completions \
  -H "Authorization: Bearer hk-你的令牌" \
  -H "Content-Type: application/json" \
  -d '{"model":"你的模型名","messages":[{"role":"user","content":"你好"}]}'
```

客户端接入只需两处：BaseURL 填 `http(s)://<hapiy 地址>/v1`，API Key 换成令牌页生成的 `hk-` Key。完整说明见站内「帮助」（`/help`）。

## ⚙️ 运行机制

安装完成后后端会一直在后台运行：登录自动启动，进程挂了自动重拉。

- **登录自启**：macOS/Linux 注册用户级服务（launchd LaunchAgent / systemd `--user`），Windows 注册登录任务（任务计划程序）。开机登录后无需手动做任何事。
- **确认自启装好了**：终端运行 `hapiy service status`。退出码 `0`=已安装且运行中、`4`=已安装但暂停（下次登录仍会自启）、`3`=未安装。安装脚本用这个码校验，装不上会直接报错退出。
- **崩溃自动重启**：macOS/Linux 由 launchd / systemd 拉起；Windows 由 `hapiy up --supervise` 守护循环负责（退出 1 秒后重拉）。日志都在 `~/.hapiy/log/hapiy.log`。
- **手动管理**：
  - `hapiy service status | start | stop | uninstall` — 查看、启动、暂停、卸载自启服务；`stop` 只是暂停，下次登录会自动恢复。
  - `hapiy serve` — 前台运行；`hapiy up` — 确保后端在跑（幂等）；`hapiy down` — 先停守护再停后端。
- **局域网**：默认监听 `0.0.0.0`，同一局域网的设备可用 `http://<本机IP>:18009` 打开。想只限本机，把启动时的 `HAPIY_HOST` 设为 `127.0.0.1`。
- **升级**：检测到新版本时，侧边栏「系统设置」会出现更新提示，进设置点「升级」即可（自动下载并重启，页面自动刷新）；也可以在终端运行 `hapiy upgrade`。
- **开发**：在源码仓库用 `./alive/alive.sh` 本地重建并运行（默认把前端构建成 prod 栈跑在 18009；`./alive/alive.sh dev` 切换 Vite 热更新，后端 8080）。构建产物写在 `~/.hapiy/app/`，与安装版、一键升级共用同一位置，互相覆盖。运行时临时暂停已安装的自启服务，下次登录自动恢复。开发细节见 `AGENT_README.md`。
