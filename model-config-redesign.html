模型配置页面（Agent 管理模型弹窗）重构原型

基于 agent-models.tsx（2244 行）现状的真实复刻与改进方案

report_problem 现状问题诊断（为什么会觉得难用？）

1. 中间栏 40% 被"供应商配置"占死

中栏硬切上下两份：上半供应商配置 JSON、下半模型列表。用户只关心模型时，模型列表仍被压缩在 60% 空间里，需频繁滚动；而供应商配置多数时候是死区。

2. 默认就是 JSON diff，门槛高

默认展示原始 JSON + 行内标签（推荐新增/推荐修改），普通用户要理解 max_context、input_types 这些字段名和枚举含义，学习成本高。

3. 问题不显眼，全靠逐个点

模型列表行没有"有 diff"标记，用户不知道哪个模型有问题，只能逐个选中查看右侧配置；全页也没有总体健康度概览，无法快速定位需要修复的对象。

4. 无搜索、操作藏得深

供应商/模型列表均无搜索过滤；"使用推荐值"依赖 hover 才可见（触屏直接失效）；要改一个字段需先进"编辑"模式切到裸 JSON 手写。

lightbulb

具体改进点清单

monitor_heart 1. 顶栏健康度摘要 + 面包屑

全页一眼看到「哪些供应商/模型有问题、共几处」；点击数字自动过滤列表直抵问题项。当前选中对象以面包屑固定在标题栏，避免迷失。

format_list_bulleted 2. 列表全部加搜索 + 行内问题徽章

供应商/模型列表均可搜索过滤；每行箭头显示「⚠N 不一致 / ✚N 缺失 / ✓ 符合」，有问题一眼可见，无需逐个点开。

tune 3. 右栏配置改为表单视图（JSON 保留）

每个推荐字段 = 中文名 + 原始 key + 说明 + 输入控件 + 状态。普通用户改值零门槛；右上角「JSON」仍保留给高级用户手写。

mouse 4. 操作按钮常显 + 一键盘点

「采用推荐 / 添加」按钮常显（触屏可用）；每模型/供应商/全页提供「一键采用全部推荐」，减少重复点击。
